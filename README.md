# 内部規定集 整備支援 操作デモ

保険代理店の内部規程集を対象に、**「備えておくべき資料」の該当箇所を自動で洗い出し、不足している規程を根拠つきで確定する**支援のデモです。

**デモ:** https://ktamura-art.github.io/regulation-mapping-demo/

---

## 何を解決するか

代理店では、業界団体が示す「備えておくべき資料」の一覧に対して、自社の内部規程集や業界ガイドのどこに該当記載があるかを探し、該当ページをPDF化して備置する運用が行われています。

この「探す」工程が負担の中心です。

- 内部規程集131ページ＋業界ガイド218ページを横断して探す
- 複数名で分担しても、探し方も記録の仕方も人によって異なる
- 見つからないときに「本当に無いのか」を確定できない
- 規程は毎年改定されるため、翌年また同じ作業が発生する

## デモの範囲

| タブ | 内容 |
|---|---|
| 該当箇所マッピング | 備置要求項目30件に対する判定（該当あり／要確認／要作成）、該当規程・ページ・**根拠となる条文抜粋**・確信度。行をクリックすると判定理由が出ます |
| 要作成リスト | 該当が見つからなかった5件。「探したが無かった」根拠つきで、そのまま作成対象として確定できます |
| 規程ひな型 | 既存12規程から抽出した**共通の章立てパターン**と、それに沿って作成した「事故対応に関する業務規定」のドラフト |
| 処理の流れ | 取込 → 構造化 → 項目展開 → 突合 → 根拠付与 → 生成 の6工程を実行ログつきで再現 |

## 設計上のポイント

**1. 既存の規程には「型」がある**

既存12規程の章立てを解析すると、**総則 → 体制・役割 → ○○マニュアル等 → 適切な○○の実施 → 評価・改善活動 → 罰則** という共通パターンが現れます。不足している規程もこの型に当てはめれば、既存と違和感のない体裁で作成できます。

**2. 「該当なし」にも根拠を付ける**

見つからなかった項目こそ判断が必要です。「どこを探して、なぜ無いと判断したか」を必ず添えます。

**3. AIが黙って捨てない**

30項目すべてに判定理由が付きます。確信度がしきい値（0.70）未満のものは「要確認」として人の判断に回し、AIが勝手に「該当あり」と断定しません。

**4. 業務内容はAIに推測させない**

規程ドラフトの章立て・文体は既存規程から機械的に抽出しますが、**実務の中身はヒアリングに基づいて記載**します。最終的な内容の妥当性判断は依頼元が行う前提の設計です。

## 注意

- 本デモは操作イメージの確認用です。**掲載の項目・規程名・ページ番号・抜粋文はすべて架空のサンプルデータ**で、実在の代理店の規定集および損害保険協会の資料は使用していません。
- 単一の `index.html` のみで動作します（外部依存なし）。
